## 一、这些文件是什么

它们是**旧基线脚本（baseline_v3 ~ v6）的特征缓存**，产生于早期探索阶段（MFCC 手工特征路线），
已被 `output_whisper/`（whisper 深度嵌入）完全取代。

### 具体组成

| 文件 | 大小 | 内容 |
|---|---|---|
| `output_v3/test_inset_feats.pkl` | 13.8GB | baseline_v3 提取的 **test 100K 每对 enroll/query 的 MFCC+delta+delta2 帧级特征**（未压缩、逐帧存数组，所以巨大） |
| `output_v3/test_outset_feats.pkl` | 13.8GB | 同上，outset 一半 |
| `output_v3/all_features.pkl` | 2.8GB | baseline_v3 训练用 val 10K 的 MFCC 特征缓存 |
| `output_v4/all_features_v4.pkl` | 2.8GB | baseline_v4 的同类型缓存 |
| `output_v5/all_features_v5_audio.pkl` | 4.4GB | baseline_v5 音频特征缓存 |
| `output_v6/all_features_v6_video.pkl` | 2.8GB | baseline_v6 视频(lipreading)特征缓存 |
| `output_v3/noise_feats.pkl` | 57MB | 噪声增强样本特征（小，可忽略） |
| `output_v4/noise_feats_v4.pkl` | 57MB | 同上 |
| `output_v6/noise_feats_v6.pkl` | 57MB | 同上 |

**合计约 40GB**。各目录下还有 23 个 `best_*.pt` 权重（单个几十 MB），它们不属于这 40GB，但本次一并删除，来历见下一节。

### 特征类型细节

关键点：全是**传统 MFCC 手工特征**，不是深度嵌入。

- 提取函数：`scripts/baseline/baseline_v3.py` 中的 `extract_mfcc_feats()`
- 参数：40 维 MFCC + delta + delta2（共 120 维），`n_mels=80, n_fft=512, hop_length=160, win_length=400`
- enroll 截取 2.0s、query 截取 4.0s，帧级数组逐帧存储 → pkl 巨大（13.8GB 一个）

## 二、被删除的模型权重（来历）

这 23 个 `best_*.pt` 全部是**早期本地基线**的 `state_dict`，由 `scripts/baseline/` 下的脚本在 10K val 上用 MFCC 帧级特征训练产生。它们不是最终提交模型，和 `output_p1~p4`（whisper 嵌入 + Matcher，p4 线上 0.82755）是两条完全不同的技术路线。

### output_v3（`baseline_v3.py`，KWSpotterV3：120 维 MFCC 帧级 CNN + attention pooling）

| 权重 | 来历 |
|---|---|
| `best_base.pt`、`best_big.pt`、`best_long.pt`、`best_wide.pt` | 初轮 4 组超参搜索；其中 `wide` 对应线上 **0.6466**（归档提交 `submission/submit_v3_auc0.6466.csv`），被后续脚本写成 `prev_best_auc=0.6466` |
| `best_lr1e3.pt` | 第二轮：lr 1e-3 / bs 64 / hidden 256 / 50 epoch |
| `best_wide_long.pt` | 第二轮：lr 3e-4 / bs 128 / hidden 320 / 70 epoch |
| `best_big_lowlr.pt` | 第二轮：lr 2e-4 / bs 64 / hidden 384 / 60 epoch |
| `best_mid.pt` | 第二轮：lr 5e-4 / bs 96 / hidden 256 / 50 epoch |
| `best_final.pt` | 第二轮：lr 3e-4 / bs 128 / hidden 320 / 80 epoch |
| `best_model_v3.pt` | 上述最优配置的副本，作为 v4/v5/v6 的统一基线 |

### output_v4（`baseline_v4_loop1.py`，KWSpotterV4：V3 音频 + 字符级文本编码器 + Focal Loss）

| 权重 | 配置 |
|---|---|
| `best_v4_base.pt` | lr 1e-3 / hidden 320 / text_dim 256 / γ=2.0 |
| `best_v4_wide.pt` | lr 5e-4 / hidden 384 / text_dim 320 / γ=1.5 |
| `best_v4_bigtext.pt` | lr 3e-4 / hidden 320 / text_dim 384 / γ=2.0 |
| `best_v4_focal3.pt` | lr 5e-4 / hidden 320 / text_dim 256 / γ=3.0 |
| `best_v4_deep.pt` | lr 2e-4 / hidden 384 / text_dim 320 / γ=2.0 |

目录里没有 `best_model_v4.pt`，说明 5 组配置都没有超过 V3 的 0.6466（脚本只在超过基线时才复制这份副本）。

### output_v5（`baseline_v5_multimodal.py`，KWSpotterV5：whisper 音频 + 唇读视频 + 文本，cross-attention）

| 权重 | 配置 |
|---|---|
| `best_v5_base.pt` | lr 1e-3 / hidden 256 / text_dim 128 |
| `best_v5_wide.pt` | lr 5e-4 / hidden 320 / text_dim 160 |
| `best_v5_deep.pt` | lr 3e-4 / hidden 320 / text_dim 192 |

搜索表里的 `v5_big`、`v5_long` 两组没有留下权重，说明这一轮没有跑完；同样没有 `best_model_v5_audio.pt`，即没有超过 0.6466。

注意：根目录 `train_matcher_v5.py` 也把输出目录写成 `output_v5`，但它读取的 `output_whisper/train_feats.npz` 从未生成（见 `docs/history/PROGRESS.md`），所以 `output_v5` 里没有它产出的 `best_v5.pt`——这些权重全部来自 baseline_v5。

### output_v6（`baseline_v6_multimodal.py`，KWSpotterV6：V3 MFCC 音频 + 唇读视频，不加文本）

| 权重 | 配置 |
|---|---|
| `best_v6_base.pt` | lr 1e-3 / hidden 256 |
| `best_v6_wide.pt` | lr 5e-4 / hidden 320 |
| `best_v6_video.pt` | lr 3e-4 / hidden 320 |
| `best_v6_deep.pt` | lr 2e-4 / hidden 384 |
| `best_v6_long.pt` | lr 3e-4 / hidden 320 / 80 epoch |

`results_v6_video.json` 是这轮的 val AUC 汇总，随目录删除；同样没有 `best_model_video.pt`。

### 为什么没有保留价值

- 线上只有 **0.6466**（归档提交 `submit_v3_auc0.6466.csv`），而 p4 线上 0.82755、多模板路线 0.89995，起点和终点都低得多。
- 特征路线是 MFCC 手工特征，已被 `output_whisper/` 的 whisper 嵌入取代；保留权重也无法脱离已删的特征缓存做推理。
- 最终线上成绩 0.89995 / 0.90042 来自 p4 + 无监督多模板 + DTW，与这些权重无关。

## 四、删除影响评估

### ✅ 删除后不受影响
- 当时的最优提交及所有活跃实验
- `output_whisper/`（核心特征）
- 最终模型权重（`output_p1~p4/`）
- zip 压缩包、train/test/val 原始数据

### ⚠️ 代价
- 旧基线脚本（baseline_v3~v6、`make_submission.py`）**不能再直接重跑**：权重与特征缓存都已删除。
- `train_matcher_v5.py`（输出到 `output_v5`）同样失效；它本来也因缺少 500K 特征而未成功运行过。
- 这些旧基线已被 p4 声学模型 + 无监督多模板路线取代，**无复现价值**。

### 删除时的方案选择（已执行第 3 种）

1. 先移到回收站/临时目录，观察几天再彻底清除
2. 只删 `test_inset_feats.pkl` + `test_outset_feats.pkl`（27.6GB），保留 `all_features*` 供旧脚本重跑
3. **全部删除 `output_v3`~`output_v6`（2026-10-20 实际执行，释放 40.2GB）**

## 五、相关背景备忘（项目当前状态）

- 任务：MISP-QEKS 多模态开放词汇关键词检索，判断 query 音频是否说 enroll 关键词（英文单词）
- 评分：`0.5×AUC_inset + 0.5×AUC_outset`，每天限 3 次提交
- **截至 2026-08-06 的最优：0.89995**（`submit_mt_gf_split.csv`，无监督多模板 + p4 融合；最终为 0.90042）
- 核心方法：同词全部 enroll 音频作模板（全局嵌入 + 帧级嵌入），query 取最大相似度（无监督），
  与监督模型 p4 按 split 加权融合；关键优势是无监督、不过拟合录音风格
- 历史成绩：submit_p4_full.csv 0.82755（基线）→ submit_mt_split.csv 0.89143 → submit_mt_gf_split.csv 0.89995 → submit_gf_dtw.csv 0.90042（最终）
- 待测：`submit_base_mt_v1~v3.csv`（whisper-base 嵌入多模板融合，预期 0.90-0.91）
- 已确认结论：val 内评估系统性虚高（与 test 同分布但独立录音），只有提交实测可靠；
  train 500K 数据因录音环境偏移（与 test 余弦 0.945）基本无效；ASR 路线在 test 上命中率 <10% 已废弃
