### ==多模态==
# **一、赛事背景**

随着智能语音交互技术的快速发展，关键词检索（Keyword Spotting, KWS）已广泛应用于智能助手、智能家居、车载交互、会议系统以及可穿戴设备等场景。传统关键词检索系统通常依赖固定关键词集合，并主要基于单一语音模态进行建模。然而，在真实应用环境中，远场采集、背景噪声、多人重叠说话以及设备信道差异等问题会显著降低系统性能。同时，固定关键词体系难以满足用户自定义关键词的开放场景需求。

近年来，Query-by-Example Keyword Spotting（QEKS）逐渐成为关键词检索的重要研究方向。相比传统固定词表方法，QEKS允许用户通过示例语音或文本动态定义关键词，从而具备更强的开放词汇泛化能力。然而，现有QEKS研究大多仍局限于音频单模态建模，在复杂噪声环境下容易出现误检、漏检以及泛化能力不足等问题。此外，目前公开数据集大多规模有限，缺少统一的大规模、多模态、开放词汇评测基准，制约了相关算法的发展与公平比较。

为推动复杂真实场景下开放词汇关键词检索技术的发展，本次赛事基于中国科学技术大学国家语音及语言信息处理工程研究中心（NERC-SLIP）开源发布的 MISP-QEKS 数据集开展。MISP-QEKS 是首个面向开放词汇关键词检索的大规模文本-语音-视频三模态数据集，包含约19万小时级别的多模态数据、超过61万个 enrollment-query 样本对以及9830个关键词，覆盖真实环境噪声、多说话人场景以及开放词汇测试条件。数据集同时构建了 Seen 与 Blind（Out-of-Vocabulary）评测集，用于系统评估模型在已知关键词与未知关键词上的泛化能力。

本次赛事鼓励参赛者探索多模态融合、开放词汇关键词建模、鲁棒语音表征学习以及跨模态对齐等关键技术，重点提升模型在真实复杂环境中的鲁棒性与泛化能力，推动下一代智能语音交互系统的发展与落地应用。

# **二、赛事任务**

本次赛事基于 MISP-QEKS 大规模多模态开放词汇关键词检索数据集开展，任务目标为：在给定 Enrollment（注册样本）与 Query（查询样本）的条件下，判断 Query 中是否包含与 Enrollment 对应的目标关键词。

与传统固定关键词检测任务不同，本赛题采用 Query-by-Example Keyword Spotting（QEKS）设置，不预先限定关键词词表，系统需具备对未见关键词（Out-of-Vocabulary, OOV）的泛化能力。参赛者需要充分利用文本、语音与视觉三模态信息，构建鲁棒的开放词汇关键词检索模型。

具体而言，每个样本对由以下内容组成：

1. Enrollment（注册端）

  Enrollment Audio：目标关键词对应的注册语音；   Enrollment Video：与注册语音同步的人脸口唇视频；   Enrollment Text：目标关键词对应的文本信息；

2. Query（查询端）

  Query Audio：待检测语音；   Query Video：与查询语音同步的人脸口唇视频；

参赛模型需根据 Enrollment 与 Query 的多模态信息，输出Query 包含目标关键词的概率，提交字段包括：  
id,type,prediction  
0,inset,0.85  
1,inset,0.12  
2,inset,0.95  
3,inset,0.34

为更贴近真实应用场景，赛事数据包含真实环境噪声、多种信噪比条件以及开放词汇测试集。测试集中既包含训练阶段已出现的关键词（Seen Keywords），也包含训练阶段未出现的关键词（Blind / OOV Keywords），重点考察模型在复杂环境下的鲁棒性与泛化能力。

# **三、评审规则**

1.数据说明

本次赛事基于 MISP-QEKS 数据集开展。MISP-QEKS 是面向开放词汇关键词检索（Query-by-Example Keyword Spotting, QEKS）的大规模文本-语音-视频三模态数据集，包含真实环境噪声、多说话人场景以及开放词汇测试条件，重点用于评估模型在复杂真实场景下的鲁棒性与泛化能力。

数据集由 Enrollment（注册端）与 Query（查询端）组成，每个样本对均包含文本、语音与视频等多模态信息。参赛选手需基于提供的数据构建模型，判断 Query 中是否包含 Enrollment 对应的目标关键词。

本次比赛提供以下数据：

|数据类别|变量名称|数据格式|数据说明|
|---|---|---|---|
|样本信息|pair_id|string|样本对唯一编号|
|标签信息|label|int|是否包含目标关键词（1：包含，0：不包含）|
|Enrollment 文本|enrollment_text|string|Enrollment 对应关键词文本|
|Enrollment 音频|enrollment_audio|wav|Enrollment 对应语音音频|
|Enrollment 视频|enrollment_video|mp4|Enrollment 对应口唇视频|
|Query 音频|query_audio|wav|Query 待检测语音|
|Query 视频|query_video|mp4|Query 对应口唇视频|

数据集按照说话人独立（Speaker-Independent）原则划分为训练集、开发集以及测试集，具体规模如下：

|数据划分|时长（小时）|样本对数量|关键词数量|
|---|---|---|---|
|Train|157.756|500,000|8,357|
|Dev|3.245|10,000|2,247|
|Eval-Seen|15.300|50,000|2,174|
|Eval-Blind|17.305|50,000|1,445|

其中：

  Eval-Seen 中的关键词在训练集中出现过，用于评估模型对已知关键词的识别能力；   Eval-Blind 中的关键词在训练阶段未出现，用于重点评估模型对未知关键词（Out-of-Vocabulary, OOV）的泛化能力。

为模拟真实应用场景，数据集中额外引入了真实环境噪声，包括商场环境音、空调噪声、电视背景音、风扇噪声等，并在不同信噪比条件下进行混合。赛事数据同时包含一定比例的语音学相似负样本（Phonetic Hard Negatives），进一步提升任务挑战性。

比赛期间将开放训练集与开发集下载，测试集标签不公开。参赛选手需基于官方提供的数据完成模型训练与推理，并提交测试集预测结果用于线上评测。

2.评估指标

本次赛事采用 AUC（Area Under ROC Curve）作为最终评测指标，具体的说，0.5AUC_seen+0.5AUC_blind用于衡量模型对正负样本的整体区分能力。

参赛模型需对每个 Enrollment-Query 样本对输出预测结果，系统将基于模型输出结果计算 ROC 曲线，并进一步计算对应的 AUC 值。AUC 数值越高，表示模型性能越优。

AUC 指标具有对类别分布不敏感、能够综合反映模型整体判别能力等优点，适用于开放词汇关键词检索任务中的二分类评测场景。

3.评测及排行

本次赛事分别计算 Eval-Seen 和 Eval-Blind 的 AUC，综合得分为： Score = 0.5 × AUC_seen + 0.5 × AUC_blind 综合得分越高，排名越靠前。

# **四、作品提交要求**

1. 文件格式：按照 CSV 格式提交，表头包含 id、type、prediction 三列。

对于每种 type，id 均独立从 0 开始编号，取值范围为 0-49999 的整数；type 取值为 {inset, outset}，其中 inset 对应 Eval-Seen，outset 对应 Eval-Blind；prediction 为参赛模型输出的概率，取值范围为 [0,1]。

正式提交中 inset、outset 各包含 50000 行预测结果，共 100000 行数据（不含表头）。每个 (type, id) 组合必须唯一并完整覆盖。

2.文件大小：无要求

3.提交次数限制：每支队伍每天最多3次

4.文件详细说明：编码为UTF-8，第一行为表头，提交格式见样例

id,type,prediction  
0,inset,0.85  
1,inset,0.12  
2,inset,0.95  
3,inset,0.34  
…  
49999,inset,0.67  
0,outset,0.45  
1,outset,0.78  
2,outset,0.23  
...  
49999,outset,0.56

id 与测试样本文件一一对应：对于每种 type，id=0 对应 pair_000001.txt，id=49999 对应 pair_050000.txt。平台提供的 200 行文件仅作为格式示例，不代表正式提交规模。

5.不需要上传其他文件
